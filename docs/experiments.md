# 实验设计

## 综合车流

同一回合包含低流量、南北偏流、高峰、东西偏流回落四阶段。默认每 60 秒更新到达率，再叠加 ±20% 随机波动；车辆按分段泊松过程到达，直行概率约 50%，左右转各约 25%。短于 60 秒的冒烟测试可能只覆盖一个阶段，正式实验应使用 600 秒或更长。

训练每回合使用 `100000 + 训练种子 × 1000 + 回合编号` 生成新车流；评估种子限制为 0–99999，默认 101–105。每个训练种子分配 1000 个回合种子，程序会拒绝超出范围的训练。两种策略使用相同到达文件及仿真随机种子。正式实验建议至少三个训练种子，独立测试种子保持一致。

## 产物与指标

| 产物 | 内容 |
|---|---|
| model.zip、run.json | 模型、配置、训练种子、权重更新检查 |
| monitor.csv、learning_curve.png | 每回合奖励与平滑曲线 |
| summary.csv、aggregate.csv | 每个测试种子的结果及均值、样本标准差 |
| comparison.png、report.md | DQN 与固定配时对照 |
| trace.csv、tripinfo.xml | 逐步过程与行程记录 |

核心指标：平均停车等待＋入网延迟、平均排队、完成率。等待统计涵盖已完成、未完成和未入网车辆，但只计到仿真结束；不能把未完成车辆直接丢弃。各方向等待、安全事件也保存在 summary.csv。

曲线下降或波动是可能的，不能只选最好的一次。比较时保持车流、仿真时长、信号约束一致；结果不好也应如实报告。测试种子用于最终评估，调参应另留验证种子。

## 一项后续改进

固定其余条件，比较切换惩罚 0、0.2、1.0。对每个配置重复训练，分析等待、完成率和切换次数。不要同时修改车流、状态与算法，否则难以归因。

| 策略 | 等待＋入网延迟（秒） | 平均队列（辆） | 完成率 |

## 改进实验（2026-09-27）

旧模型测试种子 101 的 120 次请求中，北向 78 次、东向 42 次，南、西均为 0；实际执行南、西仅为 12、6 次。这支持检查方向饥饿，不能单凭该记录推断所有车流上的行为。

保留 `configs/default.json` 作为原版对照；`configs/improved.json` 使用 18 维状态，追加四个方向的连续未放行时间（除以 120 秒归一化）。安全层按等待时间排序，并预留其余方向最短绿灯及过渡时间，必要时优先服务等待最长的方向。该规则对 DQN 和固定配时一致生效。轨迹记录请求动作、实际动作、保护触发、各方向最长未放行时间与累计绿灯秒数。

改进配置仍使用原奖励，不新增奖励项；探索阶段占比为 0.5，预热 2,000 步。由于状态、保护及探索配置联合变化，组间差异不能完全归因于某一项，后续需要消融实验。

- 训练种子：42、43、44，各自独立车流分区。
- 验证种子：11、12、13，每 10,000 步按平均等待＋入网延迟选最佳模型。
- 新测试种子：201–210，不用于选择检查点或调参。
- 第一阶段：原版 30,000 步、改进版每种子 30,000 步。若验证表现不足，再开展预先规定的 100,000 步训练；正式测试放在模型选择结束后。
- `model.zip` 为最后模型，`best_model.zip` 为验证最佳模型，`best.json` 记录其步数；`validation.csv` 记录所有验证结果。

```powershell
.\.venv\Scripts\python.exe -m traffic_rl --config configs/improved.json train --steps 30000 --seed 42 --out outputs/my_improved_42
.\.venv\Scripts\python.exe -m traffic_rl --config configs/improved.json evaluate --model outputs/my_improved_42/best_model.zip --out outputs/my_test_42
.\.venv\Scripts\python.exe -m traffic_rl --config configs/improved.json show --model outputs/my_improved_42/best_model.zip --evaluation outputs/my_test_42 --seed 201 --no-open --out outputs/my_demo
```

每次使用新输出目录，已有实验不会被覆盖。展示页对照表对应所提供模型的独立评估，单次回放数据与多车流均值分开显示。不同训练种子的结果应分别报告，再汇总训练间波动，不能将 30 个测试回合当作 30 个独立训练模型。

### 奖励尺度对照

`configs/normalized.json` 与 improved.json 仅奖励权重不同：停车权重 0.025、切换权重 0.005，均为原值的 1/40。正数整体缩放保留两个代价的相对比例及理论上的最优策略排序，但会改变数值优化过程。不同尺度的训练奖励不能直接比较，统一使用等待秒数、排队和完成率。

2026-09-28 继续实验时，前一日的改进训练已中断，只有 1 万步检查点；奖励缩放试验未保存模型。中断目录保留作记录，不作为已完成实验。重跑采用 normalized_final42/43/44 与 guard_final42，最终使用独立测试确认结果。

仿真通信使用 SUMO 订阅，在每个 0.1 秒物理步保留碰撞和传送事件，在每秒末获取全路网车速快照。对照测试直接读取每辆车的速度，核对订阅所得的每步奖励；通信优化不改变动力学步长、车流或奖励采样频率。
